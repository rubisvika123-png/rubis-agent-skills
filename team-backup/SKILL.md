# Резервная копия команды

Каждую ночь копирует характеры, память, навыки, настройки и расписания всех агентов
на сервере в ЗАКРЫТОЕ хранилище владельца на GitHub. Секреты (токены ботов, ключи,
входы) в копию не попадают никогда: скрипт их не берёт, а если что-то похожее на
токен всё же попало в файлы — останавливается и ничего не отправляет.

Файлы навыка: `scripts/backup.sh`, `scripts/restore.sh`, `tests/test.sh`.

## Установка (владелец написал «поставь резервную копию»)

1. Попроси у владельца адрес закрытого хранилища. Владелец создаёт его сам:
   github.com → «+» → New repository → имя `agents-backup` → **Private** → Create.
   (Твой GitHub-токен из урока 4 не умеет создавать хранилища, но работать с
   созданным умеет.) Хранилище должно быть **Private** — проверь это сам на странице
   хранилища, публичное не используем ни при каких условиях.
2. Поставь rsync, если нет: `apt-get install -y rsync`.
3. Скопируй навык: `mkdir -p ~/.agents-backup && cp scripts/*.sh ~/.agents-backup/`.
4. Склонируй хранилище в `~/.agents-backup-repo`, авторизуясь своим GitHub-токеном
   (тем же, что в твоих MCP-настройках) через `git config --global credential.helper store`.
   Токен никогда не выводи в чат и в терминал.
   Если хранилище пустое — это нормально, первый запуск создаст первую копию.
5. Пробный прогон: `~/.agents-backup/backup.sh --dry-run`.
   - «Проверка ок» — дальше.
   - «СТОП: …похожее на секрет» — покажи владельцу только ИМЕНА файлов (не
     содержимое). Секрет из обычного файла перенеси в `secrets/` этого агента,
     ненужный файл с примером токена исключи. Повтори пробный прогон.
6. Первая настоящая копия: `~/.agents-backup/backup.sh`. Открой хранилище на GitHub,
   убедись, что там папка `snapshot` с агентами и файл `MANIFEST.txt`.
7. Расписание — каждую ночь в 03:30 по времени сервера. Добавь в crontab строку
   (путь к своему `secrets/channel.env` подставь свой):
   `30 3 * * * TB_NOTIFY_ENV=/root/<папка-техспеца>/secrets/channel.env /root/.agents-backup/backup.sh >> /root/.agents-backup/backup.log 2>&1`
   Если копия однажды не сохранится, владелец получит сообщение от твоего бота.
   Общая папка команды (общая память, доска задач) попадает в копию сама, если это
   `~/second-brain`. Если у команды общая папка называется иначе — добавь в эту же
   строку перед `/root/.agents-backup/backup.sh` ещё `TB_SHARED=/root/<общая-папка>`
   (несколько папок — через пробел, в кавычках).
8. Напиши владельцу одним сообщением: копия работает, сколько агентов в ней,
   хранилище закрытое, следующая копия сегодня ночью.

## Восстановление на новом сервере («восстанови команду из резервной копии»)

Сначала владелец по урокам курса готовит новый сервер и ставит на него техспеца
(то есть тебя). Дальше ты:

1. Ставишь rsync, клонируешь хранилище копии во временную папку (владелец даёт адрес).
2. Запускаешь `restore.sh <папка с хранилищем>`. Он вернёт на место характеры,
   память, навыки, настройки и расписание всех агентов и покажет, кто был в команде.
3. Для каждого агента из списка, кроме себя:
   - если у агента нет папки `dashi-plugin-claude-code` — скопируй её из своей папки
     и выполни в ней `bun install` (так же, как в уроке про маркетолога);
   - попроси у владельца токен его бота (@BotFather → /mybots → бот → API Token) и
     впиши в `secrets/channel.env` этого агента вместе с Telegram ID владельца.
4. Агенты на Hermes: поставь Hermes по уроку 10, восстановленные профили уже на
   месте; войди в ChatGPT для каждого профиля так же, как в уроке.
5. Запусти агентов (`./start.sh` / службы), владелец пишет каждому боту «Проверка».
6. Поставь резервную копию заново (раздел «Установка», шаги 3–8) — уже в то же
   хранилище.

## Если владелец получил «копия не сохранилась»

Смотри `~/.agents-backup/backup.log`. Частые причины: истёк GitHub-токен (обнови),
в файлы попал секрет (шаг 5 установки), закончилось место на диске.
